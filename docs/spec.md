# 高校物理「力の作図トレーナー」実装仕様書 v2.0

本書は、PC上のフォルダを指定して実装作業を進めるための仕様書です。第2部以降の規約は、図（SVG）と問題データ（JSON）を分担して作成する際の共通ルールになります。

---

## 第1部　システム概要

### 1.1 目的
ブラウザ上で「作用点・向き・大きさ・力の名称・力を及ぼす相手」を生徒自身に描画・選択させ、正確な力の作図力を養成する。特に、初学者が抱きやすい誤概念（運動の向きに力を描く、垂直抗力を重心から描く、向心力や遠心力を独立した力として描く等）を**入力できる状態にして検出し、フィードバックする**ことを重視する。

### 1.2 動作環境
- PC、スマートフォン、タブレット（タッチ・マウス双方に対応）
- サーバー不要の静的サイトとして動作させる（ファイルを置くだけで公開できる構成）
- 外部ライブラリは原則不要。バニラJS＋SVG／Canvasで実装する

### 1.3 学習の単位
- **問題（problem）**：1つの場面。2物体の場面は「パート」を2つ持ち、必ず連続で出題する
- **パート（part）**：1つの注目物体について力をすべて描く作業
- **セット（sceneSet）**：斜方投射の上り／最高点／下りのように、連続提示して比較させる複数問題のまとまり

### 2.1 命名規則
- 問題ID＝`単元記号 + 2桁番号`（例：`A05`、`H12`）。ファイル名・JSON内の`id`・図のファイル名をすべて一致させる
- 2物体の問題はファイルを分けず、1つのJSON内に`parts: ["a", "b"]`として持つ
- 単元記号：A=力学基礎、B=力学標準、C=剛体、D=円運動・単振動、E=非慣性系、F=流体・気体、G=電磁気、H=発展
- 番号は**欠番を作ってよい**。問題を差し替えても他のIDを動かさないこと

## 第3部　図（SVG）の作成規約

### 3.1 基本
- 1問1ファイル。`viewBox="0 0 600 400"`（横長固定）。`width`/`height`属性は付けない
- 図に**力の矢印は描かない**（矢印はアプリが描く）
- 文字は最小限。物体名（A、B）や角度（θ＝30°）程度にとどめる
- 色は直値ではなくCSS変数を使い、ダークモードとハイコントラストに対応する
  例：`stroke="var(--outline)"`、`fill="var(--body-a-fill)"`

### 3.2 必須のid・data属性
アプリは図から作用点の座標と輪郭を読み取るため、次の要素を必ず含める。

| 要素 | 属性 | 用途 |
|---|---|---|
| 注目物体 | `id="body-a"` / `id="body-b"` | 注目物体の本体。`data-role="body"` |
| 輪郭 | `data-role="outline"` | 物体の輪郭線。線幅3px |
| 作用点候補 | `data-snap="<id>"` | 不可視の`<circle r="1" opacity="0">`で位置だけ示す |
| 作用点の種類 | `data-snap-type="CENTER\|CONTACT\|ATTACH"` | 重心／接触点／糸・ばねの取付点 |
| 内向き法線 | `data-inward="<角度>"` | その作用点で物体の内側を向く向き（数学座標の度） |
| 背景物 | `data-role="scenery"` | 床、壁、斜面、糸、ばね、滑車など |

**作用点候補は「正解の点」だけでなく、誤って選ばれうる点もすべて置く。** 重心・各接触点・取付点を網羅すること（これがないと誤概念を検出できない）。

### 3.3 描画スタイル
| 対象 | 規格 |
|---|---|
| 物体の輪郭 | 3px、`var(--outline)` |
| 床・壁・斜面の線 | 3px。ハッチ（斜線）は`assets/parts/hatch.svg`を参照 |
| 糸 | 1.5px の実線 |
| ばね | ジグザグ（山6個を標準） |
| 物体Aの塗り | `var(--body-a-fill)`（薄い青） |
| 物体Bの塗り | `var(--body-b-fill)`（薄い橙） |
| 単一物体の場合 | 物体Aの色を使う |

### 3.4 作用点の丸と輪郭の関係（重要）
矢印の始点には丸（半径7px）を描く。**この丸は、物体の輪郭線の内側に接するように配置する。**

- **論理座標**（判定に使う作用点）は輪郭線上のまま保持する
- **描画時のみ**、`data-inward`の向きへ丸の半径分だけ中心をずらす
- 矢印の軸は、丸の縁（輪郭から丸の直径分内側）から描き始める

これにより、接触した2物体で作用・反作用を描いたとき、2つの丸が輪郭線を挟んで反対側に並び、「別の物体にはたらく力」であることが図から読み取れる。

## 第4部　問題データ（JSON）

### 4.1 角度の規約
- **論理角度は数学座標**：右＝0°、反時計回りが正、上＝90°、下＝270°
- SVGはy軸が下向きのため、描画時に `screenAngle = -logicalAngle` で変換する
- この変換は`geometry.js`に集約し、他のファイルで直接扱わない

### 4.3 フィールド定義

| フィールド | 内容 |
|---|---|
| `frame` | `GROUND`（慣性系）／`ACCELERATED`（加速系）。加速系は画面上部に観測者を常時表示 |
| `sceneSet` | 連続提示するセットのキー。同じ値の問題は順に出題し、最後に比較画面を出す |
| `parts[].showPreviousPart` | 直前のパートで描いた矢印を薄色で残すか（既定true、テストモードでは非表示） |
| `availableForces` | 名称パレットに出す力。**ダミー（DUMMY_*）を必ず混ぜる** |
| `availableSources` | 「何から受ける力か」の選択肢。誤答用の相手も混ぜる |
| `answers[].snap` | SVG内の`data-snap`のid |
| `relations` | 大きさの関係。`op`は`=` `<` `>`。`=`の既定許容は±15% |
| `misconception` | 誤入力のキー → `feedback.json`の誤概念コード |

ダミーは**その問題で検出したい誤概念のものだけ**を`availableForces`に入れる。全問に全ダミーを並べると選択肢が多すぎて操作の妨げになる。

### 4.5 力の戸籍表記
描いた力は、矢印の脇に次の形式で表示する。

- 既定（物理基礎向け）：`地球から受ける重力`
- 記号表記（設定で切替、解説画面と作用反作用の問題では必ず併記）：`W_A←地球`、`N_A←B`

添字は「注目物体 ← 力を及ぼす相手」の順とする。

### 4.6 全問題一覧（`data/index.json`）
出題はこのファイルを起点とする。各問題について `id / title / unit / course / tags / path / partCount / sceneSet` を持つ。ランダム出題と問題選択のフィルタはここだけを読めば済むようにする。

## 第5部　作図UI

### 5.1 操作手順
1. 力の名称を選ぶ（パレット）
2. 「何から受ける力か」を選ぶ
3. 作用点をタップ → 矢印の先端へドラッグ
4. 確定すると、描いた力の一覧パネルに追加される

### 5.2 スナップ
- **作用点**：選んだ力の種類に関係なく、すべての`data-snap`点を候補とする。タップ位置から20px以内で最も近い点へ吸着。**力の種類に応じて吸着先を変えてはならない**（誤りを入力できなくなるため）
- **角度**：15°刻みを基本とし、問題固有のアンカー（斜面角に平行・垂直、糸やばねの方向）を優先吸着として加える
- スナップ後の角度は離散値になるため、判定は一致判定とする。許容誤差（±5°）はアンカーが近接する場合の処理にのみ用いる

### 5.3 表示
- **重なるベクトル**：作用点と向きが同じ力（重力と下向きの慣性力など）、および同一直線上で逆向きに重なる力（水平面上の重力と垂直抗力）は、描画時のみ直交方向へ4〜6pxずらす。論理データは同一のまま保持する
- **力の一覧パネル**：描いた力を「名称・相手・削除」で一覧表示。指で重なった矢印を選びにくい問題を回避する
- **色**：物体Aへの力＝青系、物体Bへの力＝橙系、前パートの残存表示＝薄いグレー
- **スマホ**：作用点タップ時にルーペを表示する。取り消し（1手戻る）ボタンを常設する

## 第6部　判定とフィードバック

### 6.1 マッチング
正解集合と入力集合を1対1対応させ、次の5種に分類する。

| 判定 | 内容 |
|---|---|
| `CORRECT` | 名称・相手・作用点・向きがすべて一致 |
| `WRONG_POINT` | 名称と向きは合うが作用点が違う |
| `WRONG_ANGLE` | 名称と作用点は合うが向きが違う |
| `WRONG_SOURCE` | 名称は合うが「相手」が違う |
| `EXTRA` | 正解に対応のない余分な力 |
| `MISSING` | 描かれていない力 |

`EXTRA`と`MISSING`を必ず判定対象に含めること。このアプリの中心的な価値はここにある。

### 6.2 大きさの判定
`relations`が定義されている問題のみ、矢印の長さを比較する。`=`は既定で±15%、`<` `>`は10%以上の差を要求する。関係が未定義の力の長さは判定しない。

### 6.3 誤概念フィードバック（`data/feedback.json`）
誤概念コードごとに解説文を持つ。

```json
{
  "MC_MOTION_FORCE": "運動を続けるのに力は必要ありません（慣性）。手を離れた後、進む向きに押し続けるものはありません。",
  "MC_NORMAL_AT_CENTER": "垂直抗力は面から受ける力です。作用点は、物体が面と接しているところになります。",
  "MC_CENTRIPETAL_AS_FORCE": "向心力は、はたらいている力の合力につけた呼び名です。重力や張力とは別に、もう1本描くものではありません。",
  "MC_HAND_REACHES_B": "手が直接触れているのはAだけです。Bを押しているのはAです。",
  "MC_N_EQUALS_W": "垂直抗力は必ずしも重力と等しくありません。この場面では重力より小さくなります。"
}
```

### 6.4 一問一答モード（練習・既定）
1. 判定 → 誤りがあれば、どこが誤りかは示さず「もう一度確認してみましょう」＋段階ヒント（①重力はあるか ②触れているものは何か ③接触箇所をハイライト）
2. 2回目も誤りなら、正解を重ねて表示し、誤概念コードに応じた解説を出す
3. `showPreviousPart`が有効なら前パートの矢印を薄色で残す

### 6.5 テストモード
- 各問で「次へ」を押して進み、最後にまとめて採点する
- 前の問題へ戻れる。未解答があれば提出前に警告する
- 前パートの矢印は提出まで表示しない（作用反作用の答えが見えてしまうため）
- 結果画面で表示するもの
  - 問題単位の正答数（そのパートの力がすべて正しいもの）
  - 力1本単位の部分点
  - **誤概念別の集計**（例：「運動の向きに力を描く傾向があります：3問」）。最も価値のある出力
  - 1問ずつの見直し（自分の図と正解の重ね合わせ）
  - 日時・点数・確認コード（スクリーンショット提出の運用に使う）

### 6.6 出題範囲と採点方式
両者は独立した選択軸とする。

- 出題範囲：全問／ランダム5題／単元・タグで選択
- 採点方式：一問一答／テスト

2物体の問題は、パートa→bを必ず連続で出題する。ランダム抽出でも分割しない。両パート正解で1問正解とし、「aのみ正解」も記録する。

## 付録　実装メモ（v2.0 実装時の決定事項）

仕様書本文と実装が食い違う点、および本文に書かれていなかったため実装側で決めた点をまとめます。

### 実装で決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 作用点スナップの候補 | 力の種類では絞らないが、**注目物体の作用点だけ**を候補にする | 接触した2物体では `a-right` と `b-left` が同一座標になり、どちらか判別できないため。誤概念（別の物体に描く）は「相手」の選択で検出する |
| 重なるベクトルのオフセット | 作用点ではなく**同一直線上かどうか**で判定してずらす | 水平面上の重力（重心）と垂直抗力（接触点）は作用点が異なるが同じ直線上に重なるため |
| 矢印の押す力の流儀 | **始点方式**（作用点に矢印の始点を置く）で統一 | レビュー第1部5の推奨に従う |
| ラベルの位置 | 矢先の先に置き、図からはみ出す場合は寄せ方を変えずに位置だけ内側へ寄せる | 文字が切れるのを防ぐため |
| 名称・相手の選択後 | 図が画面外にあれば自動で図を画面中央へ戻す | パレットが図の下にあるため、スマホで選択後に図へ戻れなくなるのを防ぐ |
| `forces.json` の構造 | `{ "forces": {...}, "sources": {...} }` の2階建て | 仕様書4.4の例は力だけだったが、「相手」の表示名も必要なため |
| 誤概念コードの対応表 | `misconception` のキーに `WRONG_POINT:<key>` `WRONG_ANGLE:<key>` `WRONG_SOURCE:<key>` `MISSING:<key>` `EXTRA_TYPE:<力>` `EXTRA_SOURCE:<相手>[@<パート>]` `EXTRA_ANY` を使える | 仕様書の例（ダミー名と `EXTRA_SOURCE`）だけでは、作用点ずれ・向きずれに個別の解説を返せないため |
| `relations` の `mc` | 関係が成り立たないときに返す誤概念コードを、関係ごとに指定できる | 「N＝mg と思う」「T＝mg と思う」を区別して解説するため |
| 起動方法 | `file://` では動かないため、警告画面と `tools/serve.command` を用意 | JSONとSVGを `fetch` で読むため |
| 矢印の長さ | **5段階（40/65/90/115/140）に丸める**。ドラッグは最寄りの段階へ吸着し、確定後は一覧パネルの −／＋ で調整する | 自由長のままだと、スマホで「短く描いたつもりが8%しか短くない」という*UIの失敗*で×になるため。段階にすると生徒の意図そのものが判定対象になる |
| 判定のレベル | **3段の切り替え式**（① 矢印だけ ／ ② 名称と相手も ／ ③ 大きさも）。**既定は①**。TOPの設定と出題範囲画面の両方から切り替える | 初期は「力を過不足なく認識する」ことに集中させたいため。①では名称パレットを出さず、矢印に番号を振って一覧と対応づける |
| 矢印だけのモードの判定 | 名称で対応づけられないので、**作用点か向きのどちらかが合う**入力と正解を1対1に対応させる。誤概念は、対応づいた正解の名称から判断する | 名称を選ばせなくても「垂直抗力を重心から描く」などの誤りを検出できるようにするため |
| 矢印の太さと色 | 線幅を 4.8、矢じりと作用点の丸を大きくし、物体の塗りを中間色（薄い灰）に落とす | 物体の塗りと力の色が同系色だと矢印が沈むため。色は力のために取っておく |
| `relations` の判定 | 段階の一致・大小で判定し、許容誤差は使わない（`=` は同じ段階、`<` `>` は1段階以上の差） | 離散値になったため、±15%という許容は意味を持たなくなった |
| 合否の扱い | 「力（名称・相手・作用点・向き）」と「大きさ」を分けて表示・集計する | 「向きと作用点は正解。大きさだけ見直し」と返せるようにするため。テストでは部分点を別項目にする |
| 大小関係を問う範囲 | つりあい／作用・反作用／1本の糸の張力／cosθ による大小／加速でつりあいが破れる場合、の5類型のみ。比は問わない | 質量や摩擦係数が与えられていないと決まらない大小を問わないため |

### 仕様書のまま実装した主な点

- 論理角度は数学座標（右=0°・反時計回り）。画面への変換は `src/js/canvas/geometry.js` に集約
- 図に力の矢印は描かない。作用点の丸は輪郭の内側に接するよう `data-inward` 方向へ半径分ずらす（論理座標は輪郭上のまま）
- 判定は `CORRECT` / `WRONG_POINT` / `WRONG_ANGLE` / `WRONG_SOURCE` / `EXTRA` / `MISSING` の6種
- 一問一答は「1回目は誤り箇所を示さず段階ヒント → 2回目で正解と解説」
- テストモードは前パートの矢印を提出まで表示しない
- 進捗は localStorage（`fdt-v1`）

- 場面テンプレートからのSVG自動生成（レビュー第1部7の提案）
- セット問題の専用比較画面（いまは最終問題の結果画面に `sceneSetSummary` を表示する簡易版）
